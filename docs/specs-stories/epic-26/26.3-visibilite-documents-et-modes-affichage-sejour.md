# Story 26.3 — Visibilité propriétaire des documents + modes d'affichage du séjour

**Titre** : Étendre le contrôle de visibilité propriétaire aux documents importants et ajouter deux modes d'affichage du séjour compatibles avec le masquage

**Priorité** : P2

---

## Objectif fonctionnel

Compléter le lot 1 avec deux capacités :
- le propriétaire décide aussi de la visibilité des documents importants pour les autres profils ;
- un paramètre d'affichage permet de choisir entre une vue "progressive" (jours passés + jour courant) et une vue "complète" (tous les jours).

Les deux mécanismes doivent coexister : un élément caché par propriétaire reste caché même en vue complète.

## Règles métier exactes

### A. Visibilité des documents importants

- Chaque document possède un état de visibilité piloté par le propriétaire : `visible` ou `hiddenByOwner`.
- **Seul le propriétaire** peut modifier cet état.
- Voyageur et visiteur n'ont aucun droit de modification.
- Le propriétaire voit toujours tous les documents (y compris cachés), avec indicateur de statut.
- Les profils non propriétaires ne voient que les documents marqués visibles.
- L'état est persistant et partagé (cloud), pas seulement local.

### B. Modes d'affichage du séjour (option paramètre)

- Ajouter un paramètre de mode d'affichage du séjour :
  - `progressive` : l'utilisateur voit uniquement les jours passés + le jour courant.
  - `complete` : l'utilisateur voit tous les jours.
- Ce mode impacte les écrans de consultation du séjour (Guide, Planning complet).
- Ce mode n'annule jamais les règles de masquage propriétaire :
  - en `complete`, un lieu/document caché reste caché pour non-propriétaire ;
  - en `progressive`, on applique d'abord la fenêtre temporelle, puis le masquage propriétaire.
- Le mode est accessible depuis Paramètres.

## Cas limites

- Jour courant = 1 en mode `progressive` : seul le jour 1 est visible (hors éléments cachés).
- Voyage terminé : mode `progressive` et `complete` convergent (tous les jours passés), tout en respectant les éléments cachés.
- Document sans champ jour : reste gouverné uniquement par la visibilité propriétaire (pas par fenêtre temporelle).
- Bascule du mode pendant la session : rafraîchissement immédiat des listes sans navigation cassée.

## Critères d'acceptation testables

1. Un propriétaire peut masquer/afficher un document important et le changement est propagé aux autres profils.
2. Un voyageur/visiteur ne voit aucun contrôle de visibilité des documents et ne peut pas modifier cette donnée.
3. En mode `progressive`, un non-propriétaire ne voit pas les jours futurs dans Guide/Planning.
4. En mode `complete`, un non-propriétaire voit tous les jours mais uniquement les lieux/documents non cachés par le propriétaire.
5. Les deux fonctionnalités sont compatibles sans conflit de règles (pas d'inversion d'ordre de filtrage).
6. Aucune régression sur la logique du jeu (non impactée).

## Hors périmètre

- Planification avancée par tranche horaire.
- Visibilité différente selon chaque profil non propriétaire.
- Moteur de règles conditionnelles complexes (ex. révéler automatiquement à J+2).

## Priorité

P2

## Validation attendue

- Tests unitaires :
  - filtrage combiné (rôle + visibilité propriétaire + mode d'affichage),
  - fenêtre temporelle progressive.
- Tests d'intégration :
  - paramètres -> changement de mode -> rendu Guide/Planning,
  - visibilité documents propagée cloud,
  - compatibilité mode/masquage.
- Tests RTDB rules : seules identités propriétaire autorisées en écriture des états de visibilité.

## Contraintes techniques

- Prévoir un schéma cloud explicite pour la visibilité des documents (et réutiliser celui des lieux si possible).
- Garantir l'ordre de filtrage stable :
  1) autorisation d'accès écran,
  2) mode d'affichage temporel,
  3) visibilité propriétaire.
- Ne pas coupler ces règles à la logique Jeu/Score.
