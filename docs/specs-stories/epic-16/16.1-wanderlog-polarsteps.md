# Story 16.1 — Ouverture du lien Polarsteps

**Titre** : Bouton Polarsteps : ouvrir l'application native si installée (mobile), sinon le site web — dans tous les cas, dans un nouvel onglet/une nouvelle fenêtre

**Priorité** : P3

---

## Note de fusion

Cette story fusionne les trois items initiaux du backlog (6.1 Wanderlog, 6.2 Polarsteps, 6.3 nouvel onglet) car ils partagent le même mécanisme technique : ouverture conditionnelle app-ou-web, avec le même comportement de nouvel onglet.

**Mise à jour (2026-07-31)** : le bouton Wanderlog a été retiré de l'écran d'accueil de l'application. Seul le bouton **Polarsteps** subsiste (`EXTERNAL_APP_LINKS` dans [App.tsx](../../../src/app/App.tsx)). Le reste de cette story ne concerne donc plus que Polarsteps ; les mentions de Wanderlog ci-dessous sont conservées uniquement pour l'historique de la fusion.

## Objectif fonctionnel

Depuis l'écran d'accueil, le bouton **Polarsteps** doit :
- ouvrir l'application native correspondante si elle est installée sur l'appareil (smartphone Android/iOS),
- sinon rediriger vers le site web correspondant,
- dans tous les cas, sans jamais bloquer ou remplacer l'écran de l'application de voyage en cours (nouvel onglet/nouvelle fenêtre).

## Investigation technique — résultat (2026-07-31)

Il fallait d'abord déterminer si Polarsteps a configuré des **Universal Links** (iOS) / **App Links** (Android) sur son domaine — cela détermine complètement l'approche technique à suivre.

**Vérification effectuée** : récupération publique des fichiers de vérification sur `polarsteps.com`.

- `https://polarsteps.com/.well-known/apple-app-site-association` → HTTP 200, JSON valide :
  `{"applinks":{"apps":[],"details":[{"appID":"DH3BP5LCYL.com.polarsteps.Polarsteps","paths":["NOT /about","NOT /privacy","NOT /terms-of-use","NOT /cookie-policy","NOT /teleporter","NOT /email_unsubscribe","NOT /legal/*","NOT /plus","*"]}]}}`
  → Universal Links iOS bien configurés, portée `*` (tout le domaine sauf quelques pages légales/marketing exclues). La racine `https://polarsteps.com` (utilisée par le bouton) est couverte.
- `https://polarsteps.com/.well-known/assetlinks.json` → HTTP 200, JSON valide avec plusieurs entrées `android_app` (`com.polarsteps`, etc.) portant la relation `delegate_permission/common.handle_all_urls`.
  → App Links Android bien configurés avec la permission `handle_all_urls`, requise pour l'ouverture automatique de l'app sans invite de sélection.

**Conclusion : Scénario A confirmé.** Polarsteps gère correctement les Universal Links/App Links. Il n'est donc **pas nécessaire** d'implémenter le mécanisme de repli par schéma d'URL personnalisé (Scénario B) : ouvrir le lien https standard dans un nouvel onglet suffit, le système d'exploitation se charge d'ouvrir l'app native si elle est installée.

## Implémentation

Le bouton Polarsteps ([App.tsx](../../../src/app/App.tsx), section « Photos du séjour ») est déjà un lien standard :

```tsx
<a
  href={item.href}           // "https://polarsteps.com"
  target="_blank"
  rel="noopener noreferrer"
  referrerPolicy="strict-origin-when-cross-origin"
  className="... active:scale-95 transition-transform"
>
```

Compte tenu du Scénario A confirmé ci-dessus, cette implémentation couvre déjà l'ensemble des règles métier et cas limites de cette story, sans code additionnel :
- **Mobile (Android/iOS)** : le clic déclenche une navigation standard vers `https://polarsteps.com` ; l'OS intercepte via Universal/App Links et ouvre l'app Polarsteps si installée, sinon le navigateur affiche le site web. Aucune popup, aucun message d'erreur en cas d'app absente (comportement natif de l'OS).
- **Ordinateur** : `target="_blank"` ouvre le site dans un nouvel onglet, sans remplacer l'onglet de l'application de voyage.
- **Retour visuel au clic** : la classe `active:scale-95 transition-transform` donne un état pressé immédiat, avant même que la redirection ne s'exécute.

Aucune modification de code n'a donc été nécessaire pour cette story ; le travail restant est la validation manuelle sur appareils réels (voir ci-dessous).

## Règles métier exactes

- Sur smartphone (Android/iOS), cliquer sur le bouton Polarsteps ouvre l'application Polarsteps si installée, sinon le site web.
- Sur ordinateur, le comportement actuel (ouverture du site web) est conservé, dans un **nouvel onglet**.
- Dans tous les cas (app ou web), l'ouverture ne doit jamais remplacer ni bloquer l'écran de l'application de voyage en cours.

## Cas limites

- Universal Links désactivés par l'utilisateur dans les réglages système (possible sur iOS/Android) → repli naturel vers le site web, comportement acceptable.
- Navigateur intégré (in-app browser d'une autre app, ex. réseau social) → les Universal Links peuvent être moins fiables dans ce contexte ; le repli vers le web reste un comportement acceptable.

## Critères d'acceptation testables

1. Sur Android avec Polarsteps installé, cliquer sur le bouton ouvre l'application native.
2. Sur Android sans Polarsteps installé, cliquer sur le bouton ouvre le site web dans un nouvel onglet.
3. Mêmes comportements sur iOS.
4. Sur ordinateur, le bouton ouvre le site web dans un nouvel onglet, sans remplacer l'onglet de l'application de voyage.
5. Dans tous les cas testés, l'application de voyage reste immédiatement accessible après le clic (pas de blocage, pas de perte de contexte).

## Hors périmètre

- Toute intégration technique poussée avec l'API de Polarsteps (partage/synchronisation de données) — uniquement un lien de redirection.
- Le contenu ou fonctionnement propre de l'application Polarsteps, hors de notre contrôle.
- Lien vers un voyage/journal Polarsteps spécifique (le bouton pointe vers la page d'accueil `https://polarsteps.com`) — non demandé par cette story.

P3.

## Validation attendue

Tests manuels sur appareils réels (Android et iOS, avec et sans l'app Polarsteps installée), test sur ordinateur (Chrome, Edge, Safari).

**Statut (2026-07-31) : validé.** Testé et confirmé fonctionnel par l'utilisateur en conditions réelles.

## Contraintes UX

- Aucune popup ni message d'erreur ne doit apparaître si l'app n'est pas installée — juste une redirection fluide vers le web.
- Le bouton doit rester visuellement réactif (état "au clic") le temps que la redirection s'exécute, pour éviter une impression de bouton qui ne répond pas.
