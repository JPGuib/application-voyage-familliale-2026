# Story 28.4 — Badge de messages non lus sur l'icône Chat

**Titre** : Afficher un indicateur visuel de messages non lus sur l'icône Chat et par conversation

**Priorité** : P2

---

## Objectif fonctionnel

Permettre à chacun de repérer d'un coup d'œil qu'il y a de nouveaux messages, sans avoir à ouvrir systématiquement la rubrique Chat.

## Règles métier exactes

- L'icône "Chat" de la navigation principale affiche une pastille (badge) dès qu'au moins une conversation dont le profil courant est membre contient un message plus récent que sa dernière lecture.
- Dans l'écran de liste des conversations, chaque conversation affiche son propre compteur de messages non lus (nombre, plafonné visuellement type "9+").
- Ouvrir une conversation marque tous ses messages comme lus pour le profil courant (pas de granularité message par message).
- **Limite technique assumée** : il s'agit uniquement d'un badge **dans l'application** (et, si l'app est déjà ouverte dans un onglet, d'une notification navigateur via le mécanisme déjà existant, `notifications.ts`). Il n'y a **pas** de notification qui réveille l'appareil quand l'application est fermée (pas de Firebase Cloud Messaging en place) — à traiter comme une évolution séparée si ce besoin est confirmé.

## Modèle de données (complément à 28.1)

```
chatReadState/$familyId/$conversationId/$profileId
  lastReadAt: number   // timestamp du dernier passage sur la conversation
  authorUid: string
```

- Écriture réservée au profil concerné (self-write), même schéma que les autres marqueurs "par profil" de l'app.
- Calcul du non-lu **côté client** (pas de compteur maintenu côté serveur) : pour chaque conversation dont le profil est membre, non-lu = nombre de messages avec `createdAt > lastReadAt` (ou tous si `lastReadAt` absent, plafonné à l'historique chargé). Cohérent avec l'architecture "sans backend applicatif" déjà en place (toute la logique est calculée côté client à partir des snapshots RTDB).

## Cas limites

- Un profil n'a jamais ouvert une conversation existante (ex. ajouté à "Voyage" après coup) : tous les messages existants comptent comme non lus.
- Deux appareils du même profil (multi-device, mot de passe partagé) : `lastReadAt` doit être écrit avec le timestamp le plus récent entre les appareils, pas écrasé par un appareil resté ouvert sur un ancien état (comparer avant d'écrire, ne jamais reculer `lastReadAt`).
- Beaucoup de conversations avec non-lus simultanés : le badge global reste une simple pastille (présence/absence), pas un total agrégé de tous les messages, pour rester lisible.

## Critères d'acceptation testables

1. Un nouveau message dans une conversation dont je suis membre fait apparaître la pastille sur l'icône Chat si je ne suis pas en train de la consulter.
2. Ouvrir une conversation fait disparaître son compteur de non-lus et, si c'était la seule conversation non lue, la pastille globale.
3. `lastReadAt` ne recule jamais, y compris en cas de synchronisation tardive d'un appareil resté ouvert.
4. Le badge ne s'affiche jamais pour un profil `visiteur` (qui n'a de toute façon pas accès à la rubrique, cf. story 28.1).

## Hors périmètre

- Notification push serveur quand l'application est fermée (nécessite Firebase Cloud Messaging + logique serveur, non prévu ici).
- Compteur global agrégé (somme de tous les messages non lus toutes conversations confondues).

## Priorité

P2

## Validation attendue

Tests unitaires (calcul du non-lu à partir de `lastReadAt` et de la liste de messages, non-régression de `lastReadAt`), test d'intégration App (badge apparaît/disparaît selon navigation), test manuel multi-appareils si possible.

## Contraintes UX

Pastille discrète (point coloré ou petit nombre), cohérente avec les codes de lecture déjà connus (WhatsApp/WeChat), sans clignotement ni animation intrusive.
