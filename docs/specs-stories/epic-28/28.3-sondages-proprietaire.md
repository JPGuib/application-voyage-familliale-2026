# Story 28.3 — Sondages du propriétaire dans la conversation "Voyage"

**Titre** : Permettre au propriétaire d'envoyer un sondage (oui/non ou réponse libre) dans la conversation "Voyage", avec résultats nominatifs

**Priorité** : P3

---

## Objectif fonctionnel

Donner au propriétaire un outil rapide pour prendre le pouls du groupe pendant le voyage (ex. "On part tôt demain ?", "Comment vous sentez-vous ce soir ?"), dans l'esprit des sondages WhatsApp.

## Règles métier exactes

- Seul le profil `proprietaire` peut créer un sondage, et uniquement dans la conversation "Voyage" (jamais dans un groupe personnalisé ni en 1-to-1, cf. story 28.2).
- Un sondage se compose d'une question (texte libre) et d'un type de réponse choisi par le propriétaire à la création :
  - **oui / non** : chaque membre répond en choisissant l'une des deux options fixes ;
  - **libre ("humeur")** : chaque membre répond par un court texte libre (ex. plafonné à 100 caractères).
- Un sondage apparaît dans le fil de conversation comme un message spécial (visuellement distinct d'un message texte classique), avec un bouton/zone de réponse intégré directement dans la bulle.
- Chaque membre de la conversation "Voyage" (y compris le propriétaire) peut répondre une seule fois par sondage, mais peut modifier sa réponse tant que le sondage n'est pas clos (voir clôture ci-dessous).
- Les résultats sont **nominatifs** (on voit qui a répondu quoi), cohérent avec le fonctionnement déjà en place pour le sondage destination (story 25.2) et les votes de défi (`CloudChallengeBestVote`) — pas d'anonymat dans cette famille.
- Le propriétaire peut clôturer un sondage à tout moment (les réponses sont alors figées et affichées en lecture seule) ; un sondage non clos reste ouvert indéfiniment.

## Modèle de données (complément à 28.1)

Un sondage est un message de `kind: "poll"` dans `chatMessages/$familyId/voyage-conversation-id/$messageId`, avec un sous-nœud de réponses par profil (même schéma que `CloudDestinationSurveyVote`/`CloudChallengeBestVote` : une entrée par profil, écriture limitée à l'auteur de la réponse) :

```
chatMessages/$familyId/$conversationId/$messageId
  kind: "poll"
  pollType: "oui_non" | "libre"
  pollQuestion: string
  pollClosed: boolean          // false par défaut, passé à true uniquement par le propriétaire
  authorProfileId: string      // toujours le profil propriétaire
  createdAt: number

chatMessages/$familyId/$conversationId/$messageId/pollResponses/$profileId
  profileId: string
  value: string                 // "oui" | "non" pour pollType=oui_non, texte libre sinon
  updatedAt: number
  authorUid: string
```

Règles : écriture de `pollResponses/$profileId` réservée au profil concerné (comme les votes existants) ; écriture de `pollClosed` réservée au profil `proprietaire` ; création du message `kind: "poll"` réservée au propriétaire et uniquement sur `conversationId` = celui de "Voyage" (vérifié via `isDefaultVoyage` sur la conversation, cf. story 28.1).

## Cas limites

- Un membre tente de répondre à un sondage clos : refusé côté règles (écriture bloquée si `pollClosed = true`), message explicite côté UI ("Ce sondage est clos").
- Un profil quitte la famille (suppression de profil, story 18.3) après avoir répondu : sa réponse reste affichée avec son surnom figé, comme les autres contenus attribués (commentaires, carnet de visite).
- Le propriétaire crée un sondage "libre" sans limite perçue de longueur : appliquer la même limite que les autres champs texte courts de l'app (100 caractères), avec compteur visible.
- Un membre n'a pas encore répondu : il voit clairement l'invite à répondre en premier plan de la bulle, avant de voir les réponses des autres (évite un effet moutonnier, à confirmer comme choix UX avec Jean-Philippe si un rendu différent est préféré).

## Critères d'acceptation testables

1. Le bouton "Créer un sondage" n'apparaît que pour le propriétaire, et uniquement dans la conversation "Voyage".
2. Un sondage oui/non affiche un décompte des deux options et la liste nominative des répondants.
3. Un sondage libre affiche la liste des réponses associées à chaque auteur.
4. Un membre peut changer sa réponse à un sondage ouvert ; sa réponse précédente est remplacée, pas cumulée.
5. Après clôture par le propriétaire, plus aucune réponse ne peut être ajoutée ou modifiée, par personne.

## Hors périmètre

- Sondages à choix multiples (plus de deux options fixes).
- Sondages programmés/récurrents ("sondage quotidien" automatique — le backlog l'évoque comme CN2 mais la demande consolidée avec Jean-Philippe est un sondage déclenché manuellement par le propriétaire, pas une récurrence automatique ; à revalider si un sondage quotidien automatique est réellement souhaité).
- Export ou statistiques agrégées multi-sondages.

## Priorité

P3

## Validation attendue

Tests unitaires (agrégation des résultats oui/non, gestion de la modification de réponse), tests de règles RTDB (création réservée au propriétaire, écriture de réponse bloquée si clos, écriture de réponse limitée à son propre profil), test d'intégration App (parcours complet création → réponse → clôture).

## Contraintes UX

Le sondage doit se distinguer visuellement d'un message texte au premier coup d'œil (encadré, icône dédiée), tout en restant dans le même fil de conversation. Ton familial pour les libellés ("Sondage de l'Organisateur", pas "Sondage administrateur").
