# Story 24.2 — Configuration du code voyageur par le propriétaire

**Titre** : Ajouter dans les paramètres du propriétaire un champ pour créer/modifier le code voyageur

**Priorité** : P2

---

## Objectif fonctionnel

Permettre au propriétaire de définir le code que les membres de la famille devront saisir à la création de leur profil pour être reconnus comme "Voyageur" (story 24.1). Ce code est distinct du code propriétaire (qui sert à débloquer "On est partis").

## Règles métier exactes

- Champ visible uniquement pour le profil propriétaire dans Paramètres, cohérent avec le pattern déjà utilisé pour le code propriétaire (`ownerCodeConfigured`/`ownerCodeCurrent`).
- Le code voyageur est stocké haché, en réutilisant le mécanisme `hashOwnerCode`/`verifyOwnerCode` déjà existant (`owner-code.ts`), généralisé pour ce second secret — jamais en clair.
- Le propriétaire peut créer, consulter (afficher/masquer, comme le code propriétaire, story 13.2) et modifier ce code à tout moment.
- Modifier le code voyageur n'affecte pas les profils déjà créés (cf. story 24.1, cas limites) — seules les futures créations de profil "Voyageur" utilisent le nouveau code.

## Cas limites

- Aucun code voyageur configuré → l'affichage indique clairement "Non configuré" plutôt qu'un champ vide ambigu.
- Code voyageur identique au code propriétaire → autorisé (ce sont deux secrets indépendants), mais un avertissement peut être affiché pour recommander des codes différents.

## Critères d'acceptation testables

1. Le propriétaire voit dans Paramètres une section "Code voyageur", absente pour les autres rôles.
2. Le propriétaire peut créer un code voyageur s'il n'existe pas encore.
3. Le propriétaire peut modifier un code voyageur existant, avec confirmation.
4. Le code voyageur est stocké uniquement sous forme de hash.
5. Le propriétaire peut afficher/masquer le code voyageur en clair à la demande (comme le code propriétaire, story 13.2).

## Hors périmètre

- Envoi automatique du code voyageur aux membres (partage manuel par le propriétaire, hors app — SMS, oral, etc.).
- Expiration automatique du code.

## Priorité

P2

## Validation attendue

Tests unitaires (hash/vérification), test d'intégration Paramètres propriétaire, test manuel.

## Contraintes UX

Cohérent visuellement avec la section "Code propriétaire" déjà existante dans Paramètres, positionnée juste à côté pour éviter la confusion entre les deux codes.
