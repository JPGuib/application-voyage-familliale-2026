# Story 25.2: Sondage destination pre-deblocage + verrouillage + scoring bonifie

Status: review

## Story

As a family member,
I want to submit up to 3 destination predictions before unlock and then see final results after unlock,
so that we keep suspense before departure and reward accurate, early guesses.

## Story Requirements

### Business Goal

Ajouter un ecran de sondage destination sur le parcours pre-depart (story 25.1) avec:
- Saisie libre de 1 a 3 propositions par profil avant deblocage.
- Blocage total des modifications apres deblocage.
- Affichage des resultats sur le meme ecran une fois debloque.
- Attribution de points bonifies selon exactitude et ordre.

### Functional Rules (source user request consolidated)

1. Le sondage est disponible tant que phase = before.
2. Chaque profil peut saisir jusqu'a 3 propositions, pas plus.
3. Tant que phase = before, le profil peut modifier librement ses propres propositions.
4. Des que phase = during, toutes les propositions sont figees (aucune edition).
5. L'ecran resultat (meme ecran transforme) affiche qui a vote quoi.
6. Regle de points pour un profil eligibile:
	 - 20 points si au moins une proposition correspond exactement a la destination reelle.
	 - Bonus +10 si le profil est classe 1er parmi les bonnes reponses.
	 - Bonus +5 si le profil est classe 2eme parmi les bonnes reponses.
7. Les comparaisons de texte sont insensibles a la casse (maj/min).
8. Le score du sondage ne concerne que les profils role = utilisateur pour le total partage (coherence stories 19.2 et 24.3). Les profils proprietaire/visiteur peuvent participer au jeu d'affichage mais ne gagnent pas de points partages.
9. L'ecran de saisie doit expliquer explicitement la bonification (gamification): 20 base, +10 premier, +5 deuxieme.

### Text Matching Contract (exact word with case-insensitive behavior)

Le mot doit etre exact sur le fond semantique, mais robuste aux variations de saisie usuelles:
- trim debut/fin,
- normalisation Unicode,
- comparaison insensible a la casse.

Implementation directive:
- Utiliser une normalisation centralisee (fonction utilitaire pure) appliquee des deux cotes (saisie utilisateur et destination de reference).
- Recommandation: String.normalize("NFC") + localeCompare("fr", { sensitivity: "base" }) pour eliminer les faux-negatifs de casse/accents de composition Unicode.

## Acceptance Criteria

1. Avant deblocage, chaque profil peut enregistrer entre 1 et 3 propositions; au-dela de 3, la validation est refusee avec message explicite.
2. Avant deblocage, le meme profil peut modifier ses propositions sans limitation de nombre de modifications.
3. Apres bascule phase = during, les champs de saisie et actions de validation sont desactives pour tous les profils.
4. Apres deblocage, le meme ecran affiche un mode resultat listant au minimum: profil, propositions saisies, reponse correcte/ou non, points obtenus.
5. Le calcul de points respecte exactement: 20 base bonne reponse, +10 rang 1, +5 rang 2, 0 si faux.
6. Les egalites de timestamp sur une bonne reponse partagent le meme rang et le meme bonus, sans crash ni ordre instable.
7. Les roles proprietaire et visiteur peuvent apparaitre dans l'affichage des reponses, mais n'ajoutent pas de points au classement partage.
8. La comparaison destination attendue vs propositions est insensible a la casse et ne produit pas de faux negatif entre formes Unicode equivalentes.
9. Le texte UX de l'ecran pre-vote explique la bonification en termes simples.

### Data Contract Proposal

Proposition de schema RTDB (coherent avec patterns existants):
- families/{familyId}/destinationSurvey/{profileId}
	- profileId
	- proposals: string[] (1..3)
	- updatedAt: number
	- authorUid: string

Regle d'ecriture:
- Un profil ecrit uniquement sa propre entree.
- Ecriture interdite si phase famille = during (fige).

Regle de lecture:
- Membres famille lisent l'ensemble pour affichage resultats.

### Scoring Contract

Definition:
- goodMatch(profile) = au moins une proposition normalisee = destination normalisee.
- basePoints = 20 si goodMatch sinon 0.
- rank sur les seuls profils goodMatch eligibles score partage (role utilisateur), ordre croissant updatedAt.
- bonus: rank 1 => +10, rank 2 => +5, sinon +0.
- totalSurveyPoints = basePoints + bonus.

Egalites:
- Meme timestamp => meme rank et meme bonus.
