# Story 27.2 - Explicit offline media download and cache tracking

Status: review
Epic: 27 - Offline traveler mode
Story Key: 27-2-telechargement-cache-offline
Date: 2026-08-06
Priority: P1

## Story
As a traveler profile user,
I want to explicitly download and track offline media availability by section,
so that I can reliably read and listen to trip content in airplane mode.

## Business Value
- Turns Story 27.1 media weight gains into user-visible offline readiness.
- Reduces on-trip failure risk by making download completion and gaps explicit.
- Creates a foundation for Story 27.3 (persistence reliability) and Story 27.4 (offline visibility continuity).

## Acceptance Criteria
1. A user can trigger offline media download from the app and see per-section progress for: stay guide, important documents, history, geography-economy, culture-tradition, and tips.
2. After download completes, disabling network still allows images and audio in those six sections.
3. Interrupted downloads can resume and do not restart already completed resources.
4. Cache includes media linked to currently hidden places/documents (Option A), while UI visibility logic stays unchanged for non-owner profiles.
5. Existing JS/CSS/HTML precache behavior remains unchanged (no service worker update regression).
6. Insufficient storage or failed resources produce explicit user feedback (not silent failure).

## Scope
### In scope
- Add an explicit user flow to download offline media resources.
- Build a deterministic media URL inventory grouped by section.
- Track section status (`not-downloaded` | `partial` | `complete`) in persistent local registry.
- Cache both local media (`/images`, `/audio`) and remote media URLs (for example Unsplash URLs in culture content).
- Support idempotent retries and partial resume behavior.

### Out of scope
- Any change to visibility authorization rules (`isPlaceVisibleForRole`, `isDocumentVisibleForRole`).
- Any change to Workbox precache `globPatterns` in `vite.config.ts`.
- Encryption-at-rest of cached media.
- Offline support for game, checklist, tutorial, or settings.

## Developer Guardrails

### Technical Requirements
- Keep runtime media cache path separate from generated precache.
- Preserve current service worker registration/update flow in `src/main.tsx`.
- Reuse `isOnline` state already managed in `src/app/App.tsx` to guard download actions.
- Keep implementation deterministic and testable: pure helpers for URL extraction, section grouping, and status calculation.

### Architecture Notes
- Current PWA setup in `vite.config.ts` uses Workbox `generateSW` with `globPatterns: ['**/*.{js,css,html,woff2}']`.
- Story 27.1 excluded images from precache intentionally due to prior update race and white-screen regression risk.
- Runtime media caching should use Workbox runtime routes and/or explicit Cache Storage writes, but must not bloat the precache list.

### Source of Truth for Media Inventory
- `src/content/places.ts` (images, photo galleries, and place audio)
- `src/content/documents.ts` (document image/media references)
- `src/content/histoire.ts`
- `src/content/geographie-economie.ts`
- `src/content/culture-tradition.ts` (includes remote Unsplash URLs)
- `src/content/tips.ts`
- `src/content/generated/visites-guidees.ts` (generated HTML with embedded image/audio sources)

### Edge Cases
- Network loss mid-download: keep successful resources and mark section as partial.
- Re-run after partial failure: download only missing items.
- Remote CDN rate/availability issue: mark failed URLs and show retry affordance.
- Storage pressure or quota denial: fail gracefully with explicit message and partial state retained.
- Duplicate URLs shared across sections: cache once, account status per section via references.
