# Story 27.3 - Offline storage reliability on iOS and Android

Status: review
Epic: 27 - Offline traveler mode
Story Key: 27-3-stockage-persistant-installation-ecran-accueil
Date: 2026-08-06
Priority: P0

## Story
As a traveler profile user,
I want to be clearly encouraged to install the app on my home screen and be warned if downloaded content has disappeared,
so that the offline content I downloaded (story 27.2) is still there when I actually need it during the trip.

## Business Value
- Turns story 27.2's download flow into content that reliably survives the trip, not just a demo that works in a single test session.
- Reduces the risk of a silent, undetected failure on the road (missing photo/audio discovered only when needed, no connectivity to re-download).
- iOS (Safari/WebKit) can purge Cache Storage/IndexedDB after ~7 days of tab-only use; installing to the home screen is the primary mitigation available without native app distribution.

## Acceptance Criteria
1. A clear message invites each profile to install the app on the home screen before downloading offline content, on both iOS and Android.
2. `navigator.storage.persist()` is requested and its outcome (granted/denied/unsupported) is journaled in the app (local registry from story 27.2).
3. After installing to the home screen and completing the download, content remains available after a full app close and several days of inactivity (validated manually per story 27.6 protocol; out of scope for automated tests).
4. If part of the expected cache is missing at launch (eviction despite installation), the app reports it explicitly by section rather than showing a broken screen or a silently missing media.
5. Online behavior (no install, no offline mode) is not degraded by this story.

## Scope
### In scope
- Detect whether the app is currently running installed/standalone (iOS `navigator.standalone`, `display-mode: standalone` for Android/Chrome).
- Show a home-screen install reminder with platform-specific instructions in the offline media screen (story 27.2), before the user downloads content.
- Capture the native Android/Chrome `beforeinstallprompt` event and offer a direct "Install now" action when available.
- Request `navigator.storage.persist()` and journal supported/granted/checked-at state in the existing offline download registry.
- Verify, each time the offline media screen opens, that resources previously marked `complete` are still actually present in Cache Storage; downgrade and report any gap by section using the existing partial/complete status UI.

### Out of scope
- Any workaround for iOS's lack of Background Sync / background downloads (download stays a foreground, screen-on action per story 27.2).
- Forcing installation to use the rest of the app online - installation remains a strong recommendation, not a requirement.
- Changing the PWA manifest structure (`display: standalone` and iOS meta tags already exist) - this story only adds user-facing incitation and detection.
- The real multi-day device validation itself (covered by story 27.6).

## Developer Guardrails

### Technical Requirements
- Reuse the existing offline download registry (`src/app/offline-media.ts`, story 27.2) as the single source of truth for storage-persistence and cache-integrity state; do not create a second parallel store.
- Keep new detection/journaling helpers pure and dependency-injectable (mirrors the existing `downloadOfflineMediaSection`/`verifyOfflineCacheIntegrity` pattern) so they are unit-testable without a real browser.
- Default to the safer assumption ("not installed", "not granted") whenever a browser API is missing (e.g. `matchMedia` unavailable) instead of throwing or crashing the screen.
- Do not depend on APIs unsupported on iOS (Background Sync, Periodic Background Sync).

### Architecture Notes
- `index.html` already declares `apple-mobile-web-app-capable`, `apple-touch-icon`, etc.; `vite.config.ts` PWA manifest already declares `display: 'standalone'`. No manifest/meta changes needed for this story.
- New module `src/app/pwa-install.ts` holds install-state detection and native install-prompt capture, kept separate from `offline-media.ts` (which owns the download/cache registry) to keep each module single-purpose.

### Edge Cases
- User ignores/declines installation: app stays fully usable online; the offline screen shows a clear risk warning instead of a false guarantee.
- Very low device storage during the trip (photos taken on-site): eviction can still happen even when installed; detected at next offline-screen open and reported per section, not a crash or half-broken screen.
- User already installed the app before this story shipped: no forced re-install, only a live state check (`isRunningInstalled`).
- Browser without `navigator.storage`/`matchMedia` (older Safari, some in-app browsers, test environments): treated as "not supported"/"not installed" rather than throwing.
