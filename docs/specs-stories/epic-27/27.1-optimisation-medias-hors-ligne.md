# Story 27.1 - Media weight optimization for offline readiness

Status: review
Epic: 27 - Offline traveler mode
Story Key: 27-1-optimisation-medias-hors-ligne
Date: 2026-08-06
Priority: P1

## Story
As a traveler profile user,
I want local media assets to be significantly lighter,
so that downloading offline content is practical on mobile networks and constrained hotel Wi-Fi.

## Business Value
- Reduces offline package size before Story 27.2 download flow implementation.
- Improves first-time offline setup completion rate.
- Lowers bandwidth cost and download time for end users.

## Acceptance Criteria
1. Total size of `public/images` is measurably reduced (target range: approximately 30% to 40%) without visible rendering regressions.
2. All image assets still display correctly after conversion (no broken local paths).
3. Existing automated tests (unit/integration) remain green after path/extension updates.
4. A before/after size measurement for `public/images` and `public/audio` is documented for Story 27.2 sizing.

## Scope
### In scope
- Convert all local PNG/JPEG images under `public/images` to WebP.
- Update local content references in `src/content/*.ts` when extensions change.
- Audit MP3 bitrates and only re-encode files that are clearly over-provisioned for speech use.
- Keep a reproducible script/procedure for future reruns.

### Out of scope
- Remote hotlinked images (e.g., Unsplash URLs).
- Editorial content changes.
- Aggressive resolution/cropping changes that alter perceived composition.

## Developer Guardrails

### Technical Requirements
- Reuse lightweight script-based approach aligned with existing `scripts/convert-*.mjs` pattern.
- Do not introduce a heavy runtime/build dependency for conversion.
- Keep conversion idempotent and safe to rerun.

### Edge Cases
- Existing WebP files are left unchanged.
- If a converted WebP is invalid or unexpectedly larger with obvious quality concerns, keep source for manual follow-up.
- Remote image URLs remain untouched.
